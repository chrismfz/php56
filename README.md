# PHP 5.6 for NGM — security-patched, source-built

This is the PHP **5.6.40** source tree NGM builds and runs as a legacy runtime,
kept alive safely past php.net's end-of-life. It started from the
[`boogermann/php5`](https://github.com/boogermann/php5) fork (5.6.40 with a few
early patches, now unmaintained) and adds:

- a self-contained build (`build-php56.sh`) that compiles into `/opt/ngm/php/5.6`
  against a **private OpenSSL 3.5 LTS** (legacy provider on), a **GnuTLS libcurl**
  (so `ext/curl` can't drag a second OpenSSL into the process), the bundled
  **ionCube** loader and **Zend OPcache** — all under `/opt/ngm/php`, baked in by
  RPATH so they never collide with the host;
- a **security patch series backported by CloudLinux** and applied at build time.

NGM auto-discovers the result at `/opt/ngm/php/5.6/sbin/php-fpm`; nothing else on
the host is touched.

## Security patches — where they come from

CloudLinux keeps backporting security/bug fixes to EOL PHP and ships them, one
patch per fix, inside the **public** EA4 source RPMs at
`https://repo.cloudlinux.com/cloudlinux/EA4/`. We import the source security/bug
backports from there and drop the CloudLinux/LiteSpeed/EA4 runtime and
build-packaging patches we don't use.

- **`patches/`** — the imported series, verbatim, in apply order. Machine-owned:
  regenerated by the importer, never hand-edited. See
  **[`patches/README.md`](patches/README.md)** for the current source SRPM, the
  full CVE list, and the skip reasons.
- **`patches/series`** / **`MANIFEST.tsv`** / **`SOURCE`** — the ordered apply
  list, the full kept/skipped audit with sha256s, and the exact source SRPM.
- **`patches-local/`** — our hand-maintained overlay, which the importer never
  touches, so adaptations survive a refresh:
  - `exclude` — series entries we skip, each with a reason. On this tree most are
    **already covered by the boogermann base** (the CloudLinux hunks reject only
    on context drift, not because the fix is missing), plus a few **deferred
    non-CVE** robustness bugs.
  - `*.patch` — our own adaptations. Currently `CVE-2019-11048-rfc1867-size_t.patch`:
    the multipart body-size overflow fix, rebased onto our base (boogermann had
    already changed the pristine `int` to `unsigned int` — raising the overflow to
    4GB but not closing it; this is the full `size_t` fix).

Current base: **`ea-php56-php-5.6.40-25.el8.cloudlinux.16`**. Of the 177 imported
patches, 138 apply cleanly and 39 are excluded via `patches-local/exclude` — most
already-covered by our base, plus the two CVE-2019-11048 patches (rebased as the
local patch above) and 3 deferred non-CVE robustness bugs. **Every CVE in the
series is covered.**

Unlike the 5.3 tree, 5.6 ships `configure` and the re2c-generated files, so the
build needs no generator toolchain and no `p_option` foundation patch (5.6 has
the `p` path type / `CHECK_NULL_PATH` natively).

## Build

```sh
sudo FORCE=1 ./build-php56.sh
```

Useful env: `APPLY_PATCHES=0` builds pristine (no security series);
`RUN_REGRESSION_TESTS=0` skips the post-build suite;
`PHP_GIT_REF=<ref>` builds a specific branch/tag/commit.

## Refreshing to a newer CloudLinux release

A refresh is mechanical and the delta is reviewable:

```sh
# 1. grab the newest SRPM (see patches/SOURCE for the current one)
curl -fSLO https://repo.cloudlinux.com/cloudlinux/EA4/8.1/updates/src/ea-php56-php-5.6.40-25.el8.cloudlinux.<NEW>.src.rpm

# 2. regenerate patches/ from it (deterministic — same SRPM => identical output)
./tools/import-cloudlinux-patches.py ea-php56-php-5.6.40-25.el8.cloudlinux.<NEW>.src.rpm

# 3. review ONLY the delta, then rebuild + test
git diff patches/      # new / changed / removed fixes, and any series reordering
```

New patches land as additions; a changed fix shows as a content diff (different
sha256); a removed one as a deletion. Re-check any `patches-local/exclude` entry
the delta touches (a new upstream version of a fix we deemed already-covered may
warrant a fresh look), rebuild on a host, and merge.
